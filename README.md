# Nigga Guts Rage Training

Персональный Android PWA: Push (грудь, трицепс), Pull (спина, бицепс, пресс), Legs (ноги, дельты). В Legs присед — первое силовое упражнение, румынская тяга с гантелями — второе. Без сервера, регистрации, сторонней аналитики и внешних API. Тема: «Воронёная сталь и кровь».

## Разработка и проверки

Нужны Node.js 24 и Chromium. Приложению сборка и npm-зависимости не нужны; зависимости используются только тестами.

```sh
npm ci
npm test
npm run test:e2e
```

E2E по умолчанию использует `/usr/bin/chromium`. Другой путь: `CHROMIUM_PATH=/path/to/chromium npm run test:e2e`. Для браузера Playwright: `npx playwright install --with-deps chromium`, затем `PLAYWRIGHT_BUNDLED=1 npm run test:e2e`. Тестовый сервер автоматически обслуживает настоящий подкаталог `/Nigga-Guts-Rage-Training/`. CI запускает оба набора тестов. Для ручного запуска: `node tests/server.cjs`; открыть локальный адрес с этим подкаталогом. В облачной задаче используйте существующий checkout, отдельный worktree не требуется.

## Архитектура и данные

- `*-data.js` — упражнения и исходные ориентиры из памятки; это не реальные тренировки пользователя.
- `workout.js` — общий интерфейс, черновик, таймеры, отчёт и архивирование.
- `storage.js` — проверка схемы, совместимость ключей, расчёт завершённых рабочих подходов, восстановление JSON.
- `progression.js` — консервативная двойная прогрессия без автоматического применения.
- `home.js` — история, экспорт/импорт и редактор прошлых подходов.
- `analytics.js` — вес, условный объём, число подходов, рекорд, разница двух последних занятий и числовая история.

История остаётся в `ddx_history_v1`. Формат резервной копии `ddx-training-backup`, версия 1, сохранён. Старые ключи сессий `ddx_<kind>_v2_*` и `v4_*` поддерживаются при существующей структуре `ex/rows`; незавершённая сессия находится независимо от календарной даты. Неизвестные схемы не преобразуются догадками. Полевая проверка старых записей дополняется созданием отсутствующих карточек; исходные ключи не удаляются. Проверенный сценарий миграции — восстановление совместимой v2-сессии после полуночи. Образцов иных исторических форматов в репозитории нет.

Автосохранение выполняется при вводе. Таймер хранит абсолютное время окончания и восстанавливается после навигации. «Новая тренировка» создаёт отдельную сессию того же дня. Повторное завершение обновляет ту же запись по ID. Редактор истории сохраняет предыдущую версию в `ddx_history_revision_*`; сброс черновика сохраняет `*_recovery_*`. Эти копии также входят в экспорт. Импорт требует подтверждения, объединяет историю по ID, проверяет весь файл до записи и пытается откатить изменения при ошибке квоты. Это не транзакционная база: при аварийном закрытии браузера во время многоключевого импорта атомарность не гарантируется. Сохраняйте исходный JSON.

Вес одной гантели и вес на сторону не удваиваются незаметно в аналитике; объём условный, предназначен для сравнения одного упражнения с теми же единицами. Разминка, пропуски и невыполненные подходы исключены. Неизвестная сложность, частичное выполнение, замены, боль или дискомфорт не дают повышения. Шаг веса зависит от реального инвентаря и вводится вручную. Расчёты не являются медицинскими рекомендациями.

## Публикация на GitHub Pages

1. Выполнить проверки и объединить ветку исправлений в `main` после ревью.
2. GitHub → Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/ (root)` → Save.
3. Дождаться успешного Pages deployment в Actions.
4. Открыть `https://krovm98-alt.github.io/Nigga-Guts-Rage-Training/` по HTTPS. Все HTML, JS, CSS, manifest и `icons/` должны быть опубликованы вместе.
5. На Android Chrome открыть меню → «Установить приложение» / «Добавить на главный экран».
6. Один раз дождаться онлайн-загрузки. Закрыть приложение, включить авиарежим и проверить повторный запуск, переходы и сохранение пробной записи.
7. Экспортировать JSON и проверить восстановление на тестовом профиле перед использованием с важной историей.

Для обновления изменить имя `CACHE` в `sw.js` при каждом изменении любого кешируемого ресурса. Новый кеш загружается полностью; старая версия остаётся активной до нажатия «Доступна новая версия — обновить». Затем удаляются только кеши этого приложения. `localStorage` обновление не очищает. Не меняйте origin сайта: данные привязаны к origin браузера (не к каталогу). Разные приложения на одном origin должны иметь разные ключи. Перенос на другой домен требует экспорта/импорта.

Локальное хранилище может быть очищено пользователем, браузером или при нехватке места. Экспортируйте JSON регулярно и храните его вне приложения; никогда не публикуйте резервные копии в GitHub. Установка на физическом Android, системная клавиатура, системный размер шрифта, вибрация/звук в фоне и фактическая публикация Pages требуют отдельной ручной проверки. Полный аудит и результаты — в `AUDIT.md`.

## Каталог и упражнения текущей тренировки

В каталоге 34 упражнения из семи групп: именно столько позиций перечислено в исходном задании (в заголовке задания указано 30). Данные каталога — ориентиры из журнала, они не создают занятия в истории. Диапазоны, предполагаемые веса сгибания/разгибания ног и спорный учёт дельта-машины отмечены отдельно. Для них вес требуется ввести вручную.

В карточке нажмите «Заменить упражнение»: доступны поиск, фильтр группы, собственная история и предупреждения выбранного упражнения. «Добавить упражнение» позволяет выбрать 1–10 рабочих подходов; пробный подход идёт отдельно. Дополнительные карточки можно двигать и удалять до выполнения подходов. Повторный выбор уже имеющегося упражнения блокируется. Выполненные подходы защищают карточку от замены и удаления. Выбор сохраняется после закрытия приложения; новая тренировка восстанавливает базовый план.

`catalog.js` содержит стабильные exerciseId и однозначные соответствия прежних ID. `catalog-session.js` хранит порядок и выбор в `cards` текущего черновика. Архив сохраняет exerciseId, slotId и sessionExerciseId отдельно; исходные id и данные прежних замен остаются. Аналитика группирует по постоянному ID и единице веса, прогрессия ищет результаты во всех днях. Неизвестные ID и свободные названия замен остаются отдельными legacy-упражнениями. Преобразование идентичности выполняется при чтении, поэтому старые записи и резервные копии не переписываются. Формат JSON-копии остаётся версии 1.

Проверки: `npm test` и `npm run test:e2e` (те же команды, что в CI). Каталог входит в офлайн-кеш. Проверка физического Android остаётся ручной.

### Явное применение веса

Выбор упражнения оставляет все поля веса пустыми. В карточке раздельно показаны фактические подходы последней тренировки, надёжность рабочего веса, справочный ориентир и следующая цель. Кнопка «Применить рабочий вес» доступна после информативной пробы, требует подтверждения и заполняет только незавершённые рабочие подходы без ручных правок. Пробный и выполненные подходы сохраняются; ручные изменения переживают перезапуск.

Единая функция `catalog.js: reliable()` проверяет полноту, повторения, одинаковый вес, сложность, дискомфорт, единицы и оборудование последнего сеанса. Нестабильный последний сеанс не заменяется старым стабильным; усреднение не применяется. При отсутствии истории можно подтвердить однозначный вес из журнала . Диапазоны, предполагаемые веса и неоднозначный учёт на сторону требуют ручного ввода. Прогрессия остаётся отдельной рекомендацией.

Она включена в эту сборку и добавится в каждый новый профиль её установки. Для блока выбран `rope_pushdown` по текущему Push; рукоять в исходном отчёте не уточнена, что отмечено в записи.

Повреждённая история не заменяется, ошибка записи показывается пользователю. Удаление маркера вручную может вызвать повторную проверку наличия тренировки.

Название приложения — Nigga Guts Rage Training. Прежнее обозначение зала убрано из интерфейса и отчётов при показе; технические ключи сохранены ради совместимости. Персональная причина замены удалена. Кровавый акцент заголовка выполнен локальным CSS без внешних ресурсов; тренировочные карточки остаются без декора.

## Анимированный заголовок и разбор тренировок

Главная шапка использует локальные SVG-потёки с отрывом капель и ветвящиеся фиолетовые разряды; серии вспышек разделены длительными паузами. При `prefers-reduced-motion: reduce` анимации отключены. Эффекты не применяются к рабочим карточкам.

Под каждой записью истории доступен раскрываемый «Краткий анализ»: что хорошо, на что обратить внимание, что делать дальше. Это локальный AI-style генератор по правилам, без внешней нейросети, API и ключей. Он учитывает рабочие подходы, сложность, замены, пропуски, стабильность, ограничения общей логики рекомендаций и сравнение условного объёма с более ранними результатами того же упражнения и единиц. Повышение при неполных или неоднозначных данных не предлагается. Объём не считается оценкой техники или восстановления.

`workout-analysis.js` предоставляет `WorkoutAnalysis.analyzeWorkout(session, history, context)` и возвращает структурированные разделы. Рендер отдельно находится в `home.js`; интерфейс допускает будущий серверный провайдер. Сейчас данные никуда не отправляются. Разбор пересчитывается при открытии и редактировании истории, не записывается в localStorage и не меняет формат JSON-копий.

## Bloodstorm V2 и единая калибровка

Шапка использует встроенные SVG: отдельные вязкие потёки, блики и отрывающиеся капли с разными фазами, а также ветвящиеся фиолетовые разряды. Первый разряд виден сразу; дальнейшие серии разделены паузами. `bloodstorm.js` останавливает декоративные анимации в скрытой вкладке. Reduced motion оставляет статичный вариант. Внешние ресурсы не нужны.

`weight-calibration.js` — единый механизм для базовых карточек, каталога и замен. Статические таблицы нагрузки больше не используются движком. Новые карточки оставляют веса пустыми; существующие черновики сохраняют значения.

Предложение пробы опирается на надёжность последней тренировки, совместимую успешную пробу или явно заданный предварительный пробный ориентир из прежнего плана. Источник показывается. При нестабильной истории, неизвестном упражнении или неоднозначных единицах числовой ориентир не придумывается. Более старый пробный подход помечается датой; он не заменяет заблокированную последнюю рабочую базу.

После фактически выполненной пробы учитываются введённые вес, повторы и сложность. Уверенная информативная проба позволяет предложить повторить достоверную нагрузку, но не умножает пробный вес на коэффициент. Слишком малая проба требует промежуточной проверки, тяжёлая или болезненная — ручного посильного выбора. При исходной базе без реальных тренировок уверенность явно низкая. Повышение рассматривается отдельно по прогрессии, без подстановки.

«Применить пробный вес» меняет только незавершённую пробу. «Применить рабочий вес» после подтверждения меняет только незавершённые рабочие подходы без ручных правок. Проба, выполненные подходы и ручные значения защищены. Источник и факт применения сохраняются в черновике и JSON-копии. Изменение пробы помечает прежнее предложение устаревшим, не перезаписывая веса. При замене состояние калибровки очищается.

## Пробный подход и калибровка

Для известного упражнения поле пробного веса заполняется осторожным ориентиром автоматически при открытии новой карточки. Отдельная кнопка применения пробного веса удалена. Пользователь может изменить вес/повторы, после выполнения отмечает сложность 1–6 и завершает пробу. Модуль `weight-calibration.js` предлагает рабочий вес на основе фактической пробы и сохранённых нагрузок: при высокой сложности снижает ориентир, а при отказе и дискомфорте не рекомендует рабочий вес. Рекомендация не является точным определением силы и требует подтверждения перед заполнением незавершённых рабочих подходов. Существующие черновики и вручную введённые значения не затираются.

## Завершение тренировки и следующая цель

Кнопка «Завершить тренировку» автоматически записывает завершённую сессию в локальную историю по стабильному ID, не требует копирования отчёта и сразу показывает результаты и персональные цели прогрессии. Текстовый отчёт доступен дополнительно в раскрываемом меню. История, графики и локальный разбор доступны через «Открыть статистику».

Для завершённых рабочих подходов при одинаковом весе, полной записи, известной умеренной сложности и отсутствии боли следующая цель — прежний рабочий вес и одно дополнительное повторение. После достижения верхнего диапазона может появиться предложение повысить вес, которое **не применяется без отдельного подтверждения пользователя**. Неизвестные шаги оборудования, неполные подходы, отказ, боль и нестабильные веса исключают автоматическое повышение.

Согласованные цели сохраняются в `ddx_next_targets_v1` вместе с резервной копией и автоматически заполняют рабочие строки **только новой тренировки** соответствующего упражнения; старые черновики и завершённые подходы не перезаписываются. Данные прежних завершённых тренировок также используются, если они были записаны до установки этой функции. Хранилище остаётся локальным; экспортируйте JSON регулярно.
